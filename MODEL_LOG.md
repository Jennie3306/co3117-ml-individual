# MODEL_LOG – per-model record

## Decision Tree – Ch.2 – Depth B

- **Objective / probabilistic factorization / decision rule:** Greedy top-down tree induction (ID3/C4.5 style). At each node, choose the (feature, threshold) that maximises the impurity decrease
  `ΔI = I(S) − (|S_L|/|S|)·I(S_L) − (|S_R|/|S|)·I(S_R)`, with `I = H` (entropy, log₂) or `Gini`. Continuous features use binary splits `x ≤ t` / `x > t`. A leaf predicts the majority class.
- **Assumptions, inductive bias, expected failure modes:** Axis-aligned splits; greedy one-step look-ahead (a split that looks weak now can't be chosen even if it enables good splits later); prefers short trees built from high-gain features. Failure modes: overfitting when grown to pure leaves (high variance), bias toward features with many distinct values / thresholds, instability under small data changes.
- **Data representation & preprocessing:** `X` is a numeric NumPy array (n × d); `y` holds class labels (1-D). No scaling needed, because splits only depend on the order of the values.

- **Differences from the reference code (summary + findings when testing):**
  1. *Threshold value:* midpoints (mine, as in CART / scikit-learn) vs raw distinct values (reference). Same partitions and gain, different threshold number. A midpoint places the boundary in the middle of the gap between two observed values, which is a more neutral choice for unseen values falling in that gap; this is a design choice, not an experimentally demonstrated improvement. (Original C4.5 instead uses an actual training value: the largest value not exceeding the midpoint.)
  2. *Direction:* mine `x <= t` goes left; reference `x >= t` goes to the true/left branch.
  3. *Criteria:* mine entropy **and** Gini; reference entropy only (for classification).
  4. *Integer features (reference bug):* `divide_on_feature` checks `isinstance(threshold, int/float)` (L32). `np.unique` returns `np.int64`, which is **not** a Python `int`, so integer-valued features fall through to the categorical rule `==` (L35) instead of `>=`. `predict_value` has the same check (L153). Mine casts `x` to float, so it avoids this.
  5. *NumPy compatibility (reference bug):* `divide_on_feature` returns `np.array([X_1, X_2])` (L40). When the two sides have different sizes this is a ragged array, and on NumPy ≥ 1.24 it raises `ValueError` (reproduced with NumPy 2.4 and an unequal split). Mine keeps the two sides as separate arrays (boolean mask), so this can't happen.
  6. *Speed:* both evaluate O(n) candidates with an O(n) split each (O(n²) per feature per node). Reference builds the subsets with Python list comprehensions; mine uses a vectorised mask. Measured on one feature, n = 2000, 6 classes: reference-style search ≈ 4.2 s vs mine ≈ 0.26 s.
  7. *Tie-breaking:* both use strict `>`, so the first (smallest) threshold wins. Reference starts from `largest_impurity = 0`, so it never splits on a zero-gain threshold. Mine starts from `−∞`, so it always returns a threshold when x has ≥ 2 distinct values (gain may be 0). The tree-building code must apply a minimum-gain rule.
  8. *Missing values:* see the table row above — both silently route NaN to one branch; mine now raises `ValueError`.
  → **Fix needed after review?** Entropy, IG and the best split already matched the reference on the test cases, so no correctness fix was needed. One robustness fix was added: NaN input is now rejected (`best_threshold`, covered by `test_best_threshold_rejects_nan`).
- **Modification & evidence (Depth B):** (1) vectorised boolean-mask split instead of list comprehensions + `np.array([X_1, X_2])` → no ragged-array crash on NumPy ≥ 1.24 (reproduced with NumPy 2.4) and ≈16× faster (4.2 s → 0.26 s, one feature, n = 2000); (2) Gini criterion added next to entropy; (3) midpoint thresholds; (4) float cast avoids the `np.int64` → categorical `==` bug; (5) explicit NaN rejection. Same partitions and gains as the reference verified on the 2b example (IG = 0.610, t = 3.25 vs 3.5).
- **Hyperparameters & selection procedure:** The reference exposes `max_depth`, `min_samples_split`, `min_impurity` (= min gain) but has no post-pruning, so on HAR I benchmarked scikit-learn's CART tree instead. Search space: (a) pre-pruning `max_depth` ∈ {1, 2, 3, 4, 6, 8, 10, 12, 15, 20}; (b) post-pruning `ccp_alpha` = 10 quantiles of the cost-complexity path computed on the training part of fold 1. Selection criterion: highest mean validation macro-F1 over the 5 subject-wise GroupKFold folds (training set only; test set sealed). Limitation: the α grid comes from one fold's path, and picking the best of 20 settings on the same folds makes the best score slightly optimistic.

- **Error / limitation analysis and use-case fit:**
  1. *Over/underfitting from the depth curve:* at depth 1–2 train ≈ validation and both are low (0.23 / 0.37). This is **underfitting (high bias)**: a tree with 2–4 leaves cannot separate 6 activities. Validation rises quickly up to depth 4–6 and peaks at depth 6 (0.864). Beyond that, train keeps rising to 1.000 (depth 20) while validation slowly falls to 0.839. The train–validation gap grows from 0.08 (depth 6) to 0.16 (depth 20): **overfitting (high variance)**. Depths 6–12 are all within 0.851–0.864 with std ≈ 0.02–0.04, so the curve shows a **plateau** rather than a sharp optimum.
  2. *Effect of pruning (`ccp_alpha`):* α = 0 reproduces the unpruned tree (0.840, same as depth 20). Increasing α removes weak subtrees: train drops from 1.000 to 0.955 while validation rises to 0.868 at α = 0.00224, which also has the smallest std (0.021). Too much pruning (α = 0.16748) collapses the tree to a stump (0.228, same as depth 1). Cost-complexity pruning (0.868) and depth limiting (0.864) give practically the same score. The +0.028 gain over the unpruned tree is of the same order as the fold-to-fold std (0.021–0.031), so with only 5 folds it is a trend, not a proven improvement.
  3. *Comparison with logistic regression:* the best tree (0.868 ± 0.021) is ≈ 0.07 below logistic regression (0.934 ± 0.042), and the tree's per-fold std is still 0.02–0.03. A plausible explanation: the 561 HAR features are already engineered summary statistics, so a linear combination of many features separates the classes well. A tree must approximate such boundaries with axis-aligned, one-feature-at-a-time splits, and each split sees less data as the tree deepens. Differences between subjects (GroupKFold) make this variance worse.
  4. *Cost of my own split search on HAR:* 0.77 s per feature at n = 7352 → ≈ 7.2 min for the root node alone (561 features). My search is O(n²) per feature (O(n) thresholds × O(n) mask), so a full tree from my routine is impractical without a sorted, incremental O(n log n) scan (the approach used by scikit-learn). The 0.77 s is not directly comparable with the earlier 0.26 s (n = 2000), which was measured on a different machine with synthetic data.
  5. *Use-case fit (elderly activity monitoring):* pros — a depth-6 tree has at most 64 leaves (only 29 in practice; the pruned tree has 28), so prediction needs ≤ 6 comparisons (cheap enough to run on a phone/wearable), and its rules can be read and checked by a person. Cons — its macro-F1 is clearly below logistic regression, and a single tree is unstable across subjects. As a stand-alone model it is a baseline; a pruned tree is useful mainly for interpretability or as a building block for ensembles (Random Forest / boosting).
  6. *Confusion matrix & misclassified windows (pruned tree, pooled out-of-fold predictions; 950 of 7352 windows wrong, 12.9%):* the weakest classes are WALKING_UPSTAIRS (F1 = 0.814) and SITTING (F1 = 0.826), while LAYING is almost perfect (F1 = 0.994). The two dominant errors form one systematic failure mode: STANDING → SITTING (216 windows, 15.7% of STANDING) and SITTING → STANDING (213 windows, 16.6% of SITTING). The confusion is almost perfectly symmetric, which suggests the two postures are genuinely hard to separate rather than the tree being biased towards one of them: with a waist-mounted phone both are static, so the signal differs only slightly in the orientation of gravity. LAYING is easy because the body (and the phone) is rotated by about 90°, so the gravity direction changes completely. The second failure mode is among the three walking classes (WALKING → WALKING_UPSTAIRS 131 windows, 10.7%; WALKING_UPSTAIRS → WALKING_DOWNSTAIRS 95 windows, 8.9%; WALKING_UPSTAIRS → WALKING 91 windows, 8.5%): all three are periodic step patterns that differ mainly in the vertical acceleration component. Walking is never confused with a static posture among the top-5 errors, so the tree separates *dynamic vs static* well and fails *within* each group. Of the 10 randomly inspected errors (seed 42), 4 lie within 2 windows of a label change (rows 577, 1206, 2466, 4494) and 5 are SITTING → STANDING. Overall, 21.1% of the errors and 21.1% of the correct windows lie within 2 windows of a label change, so errors are **not** concentrated at activity boundaries: transition windows do not explain the mistakes; most of them sit inside long runs of the same activity. This still matters for Part II: an HMM that exploits label continuity could correct isolated errors inside a run. For the elderly-monitoring use case this error profile is acceptable: LAYING (the safety-relevant class) is almost never missed, and SITTING ↔ STANDING confusion only moves time between two sedentary categories.
- **Exam-ready paragraph (no code):** A decision tree is grown greedily from the root: at each node every feature and every candidate threshold (midpoints between sorted distinct values) is tried. The split with the largest impurity decrease, measured by entropy-based information gain or by Gini, is kept, and the process recurses until a stopping rule applies (maximum depth, minimum samples to split, minimum gain). Entropy is safe from log(0) because only classes present in the node are summed. Using the distinct values themselves or the midpoints as thresholds yields the same partitions; midpoints simply place the boundary halfway between observed values. Trees grown with only pre-pruning tend to overfit, which is why C4.5 adds pessimistic post-pruning and CART adds cost-complexity pruning with α chosen by cross-validation.
